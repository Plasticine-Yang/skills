# 合并既有项目

模板提供默认规则，项目文件提供已有上下文。将每一项预设与现有对应规则比较：等价则复用；缺失则补齐；直接冲突则按用户本次预设调整；其余内容保留。

## 文档

- 先读完整文件，再确定修改的章节和条目。只改对应规则，保留 surrounding sections、章节内部新增的规则、链接、说明、评论和附加列。
- `## Agent skills` 和 `## Project workflow` 各保留一个。已有等价章节可沿用，避免同时存在两个入口。
- 管理标记只标识来源，不代表整个区块可覆盖。区块内的用户新增内容与区块外同样需要保留；更新标记内部规则时采用最小 patch。
- 已有 GitHub/GitLab tracker 配置改成本地 Markdown 的操作约定，保留仍适用的项目说明。外部 issue 的已有数据保持原状；配置切换不意味着自动迁移远端 issue。
- Triaging 的默认五个状态恢复标准名称，并加入 `done`。保留额外分类和状态；已有 ticket 使用旧映射时，更新其状态和关联查询规则，保留正文、评论、依赖及非状态元数据。
- Domain 的项目路径和 multi-context 布局优先保留。仅补齐缺失的消费者规则。

## AGENTS.md 与 CLAUDE.md

总是建立或更新根目录 `AGENTS.md`。已有 `CLAUDE.md` 中独有的项目约定先合并到 `AGENTS.md`；旧 setup 的同项规则移到新入口并按预设更新。

保留 `CLAUDE.md` 的其他项目内容。将已迁移的重复 setup 章节改为一个明确指向 `AGENTS.md` 的读取指针，避免 tracker 或测试规则相互矛盾。Claude Code 的指针可用 `@AGENTS.md`；其他 agent 使用适用的文件读取方式。

## Git ignore 与已有文件

- 首次应用追加模板的 ignore 区块，保留已有条目。后续合并区块时保留项目新增的例外和注释。
- 默认放行 `.scratch/<feature>/spec.md`、`map.md`、`issues/NN-*.md`。额外的长期资料先分类，再加精确路径例外。
- 放行深层目录中的文件时，需要同时放行从 feature 目录到该文件的各级父目录。用真实路径执行 `git check-ignore --no-index`，以匹配结果为准。
- `.agent-tmp/` 和 `.worktrees/` 必须被忽略。若已有下级 `.gitignore` 或末尾的反向规则抵消模板，调整冲突的条目并验证。
- `git ls-files` 中未符合白名单的文件只是待分类项：Markdown 研究结论或正式附件可能是长期资产。确认的临时文件逐个停止跟踪并保留本地，未明确用途的文件列入结果。
- 白名单控制未来的新增跟踪，已经跟踪的文件需单独处理。Ignore 不改写 Git 历史。

## 完成检查

保留原有项目说明、额外标签、domain 布局和长期资料的 ignore 例外；移除预设同项的旧冲突，验证指针可达。重复调用后，规则保持一致，文件没有多出重复章节和管理标记。
